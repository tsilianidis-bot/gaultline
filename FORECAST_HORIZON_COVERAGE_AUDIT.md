# Forecast Horizon Standard — Coverage Audit

The rollout found and contained one fabricated Oracle fallback (`2–4 weeks`), unvalidated Opportunity Discovery display horizons, a Daily Story target-timing/reward prompt, ASHA timing generation risk, and Market Context “most likely” language. All were changed to the shared disclosure or non-predictive derived-scenario treatment.

The standard does not claim that every existing FAULTLINE signal now has a calibrated horizon. Its permanent purpose is the opposite: any existing or future output lacking a documented forecast contract visibly remains **Not Yet Established**. The next valid route to Supported timing is an independently approved, pre-registered research protocol—not an interface change, model prompt, or post-hoc target.

## Regression Guards

`server/forecastHorizon.test.ts` verifies metadata and prompt rules. `server/publicClaimContainment.test.ts` protects the Oracle fallback removal, Opportunity disclosure, Market Context derived-scenario label, ASHA instruction, and Daily Story no-timing/no-reward prompt.
